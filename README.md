# 上場企業 財務時系列

金融庁のEDINETから有価証券報告書を集めて、上場企業の財務指標の推移を毎日自動で更新するサイトです。

証券コードか会社名で引くと、売上高・営業利益・経常利益・純利益・営業CF・総資産・純資産・自己資本比率・ROE・EPS・従業員数の5年分が表として出ます。行をタップするとその指標のグラフに切り替わります。

## 仕組み

```
EDINET API
   ↓  index.py          有価証券報告書と訂正報告書の索引を作る（1日ずつ、取得済みの日は叩かない）
docs_index.json
   ↓  fetch2.py         XBRLから11指標を抽出。訂正報告書があれば重ねる
data/timeseries.csv
   ↓  build_site.py     索引ページと、証券コード帯ごとのJSONを生成
site/
   ↓  Netlify           mainへのpushで自動デプロイ
```

毎朝7時（JST）にGitHub Actionsが動きます。索引を直近30日ぶん更新し、まだ取っていない会社を600社ずつ処理します。EDINETに短時間で大量アクセスしないための上限です。索引にある約3,800社を7日かけて一巡し、以降は新しい報告書が出た会社だけを取り直します。

## 作るうえで引っかかったところ

**会計基準ごとに指標の名前が違う。** IFRSと日本基準で要素IDが別物なので、両方の系列を保持して名寄せしています。銀行の「経常収益」(`OrdinaryIncome`)と「経常利益」(`OrdinaryIncomeLoss`)のように、名前が似ていて別物のものもあります。

**日本基準の「主要な経営指標等の推移」に営業利益の欄がない。** 制度上そうなっているため、損益計算書の本体から補っています。本表は当期・前期しか載らないので、この指標だけ2年分になります。

**売上高の科目名が業種で違う。** 建設業は「完成工事高」(`NetSalesOfCompletedConstructionContracts...`)、不動産・サービス業は「営業収益」(`OperatingRevenue1...`)、収益認識基準を適用した会社は「売上収益」(`Revenue...`)。推測でパターンを書くと外すので、`probe.py` で実際の要素IDを確認してから追加しています。

**訂正報告書を誤って重ねない。** 提出日時が本体より後で、かつ訂正対象の書類管理番号が本体（または既に適用した訂正）と一致するものだけを適用します。これをやらないと前年度の報告書に対する訂正を混ぜてしまいます。

**成功したのにデータが古い、を防ぐ。** スクレイピングが0件でもスクリプトは正常終了するため、Actionsは緑のまま通ります。取得件数が前回の8割を下回ったらサイトを更新せず失敗させ、ページには実際の生成時刻を埋め込んで、4日以上あいたら警告バーを出しています。

## ファイル

| | |
|---|---|
| `index.py` | 書類索引の作成 |
| `fetch2.py` | XBRLの抽出・名寄せ・蓄積 |
| `build_site.py` | サイトの生成 |
| `template.html` | ページの雛形 |
| `probe.py` | 抽出できなかった会社で実際の要素IDを調べる診断用 |
| `data/timeseries.csv` | 蓄積された時系列 |
| `data/fetch_state.json` | どの会社をどの書類で取得済みかの記録 |

## 動かす

EDINET APIキーをリポジトリのシークレット `EDINET_API_KEY` に設定してください。

```bash
pip install -r requirements.txt

EDINET_API_KEY=xxx START=2026-01-01 END=2026-01-31 python index.py
EDINET_API_KEY=xxx LIMIT=10 python fetch2.py
python build_site.py
```
