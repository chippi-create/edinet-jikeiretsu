# 上場企業 財務時系列

金融庁のEDINETから有価証券報告書を集めて、上場企業の情報を毎日自動で更新するサイトです。

証券コードか会社名で引くと、会社ごとに7つのタブが出ます。

- **財務** — 売上高・営業利益・経常利益・純利益・営業CF・総資産・純資産・自己資本比率・ROE・EPS・従業員数の5年分。行をタップするとその指標のグラフに切り替わります
- **事業** — 事業の内容（有報の本文をそのまま。系統図は画像なので入りません）。「AIで要約する」ボタンで要点をまとめられます
- **配当** — 配当政策
- **リスク** — 事業等のリスク（1社2万字ほどあるため、タブを開いたときだけ読み込みます）
- **株主** — 所有者別状況（金融機関・外国法人等・個人その他などの区分ごとの株主数と持株比率）と、大株主の状況（上位10名の氏名・住所・所有株式数・比率）
- **役員** — 役職名・氏名・生年月日・所有株式数。行をタップすると略歴が開きます
- **原本** — EDINETの原本へのリンクと、本サイトに載っていないものの一覧

## 仕組み

```
EDINET API
   ↓  index.py           有報・訂正有報・大量保有報告書・変更報告書の索引を作る
                         （1日ずつ、取得済みの日は叩かない）
docs_index.json
   ├→ fetch2.py          XBRLのCSVから指標を抽出。訂正報告書があれば重ねる
   │                     → data/timeseries.csv
   └→ fetch_sections.py  提出本文書ZIPのHTMLから、3つの表と3つの文章を抽出
                         → data/ownership.csv / shareholders.csv / officers.csv
                           data/business.csv / dividend.csv
                           data/risks/<コード>.txt  data/bios/<コード>.json
   ↓  build_site.py      索引ページと、証券コード帯ごとのJSONを生成
site/
   ↓  Netlify            mainへのpushで自動デプロイ
```

GitHub Actionsが1日1回動きます。索引を更新し、財務と記述部分をそれぞれ600社（提出本文書ZIPは大きいので時間がかかります）取って、サイトを作り直すまでを1つのジョブで通します。この社数は、EDINETに短時間で大量アクセスしないための上限です。索引にある約3,800社を一巡したあとは、新しい報告書が出た会社だけを取り直します。

実行時刻は朝7時（JST）を指定していますが、GitHubのスケジュール実行は混雑時にキューで待たされます。実測では30〜90分遅れて8時台に走ることが多く、指定側では制御できません。1日1回まわれば足りる性質なので、遅延は承知のうえで許容しています。

**生成物を書くジョブは1つだけにしています。** 以前は財務と記述部分を別のワークフローに分けていましたが、どちらも `data/` と `site/` を書くため、同時に走ると生成されたJSONが add/add で衝突し、rebase が detached HEAD で止まって push できませんでした。

## 作るうえで引っかかったところ

**会計基準ごとに指標の名前が違う。** IFRSと日本基準で要素IDが別物なので、両方の系列を保持して名寄せしています。銀行の「経常収益」(`OrdinaryIncome`)と「経常利益」(`OrdinaryIncomeLoss`)のように、名前が似ていて別物のものもあります。

**日本基準の「主要な経営指標等の推移」に営業利益の欄がない。** 制度上そうなっているため、損益計算書の本体から補っています。本表は当期・前期しか載らないので、この指標だけ2年分になります。

**売上高の科目名が業種で違う。** 建設業は「完成工事高」(`NetSalesOfCompletedConstructionContracts...`)、不動産・サービス業は「営業収益」(`OperatingRevenue1...`)、収益認識基準を適用した会社は「売上収益」(`Revenue...`)。推測でパターンを書くと外すので、`probe.py` で実際の要素IDを確認してから追加しています。

**訂正報告書を誤って重ねない。** 提出日時が本体より後で、かつ訂正対象の書類管理番号が本体（または既に適用した訂正）と一致するものだけを適用します。これをやらないと前年度の報告書に対する訂正を混ぜてしまいます。

**大量保有報告書は「保有する側」が出す。** 索引の `secCode` は提出者のもので、どの会社についての報告かは `issuerEdinetCode` を見ないと分かりません。個人が提出者の場合は `secCode` が空になります。索引には入れていますが、会社ごとに紐づけて使うところはまだ作っていません。過去ぶんを取り込むには `edinet-index` を `redo=1` で走らせて、取得済みの日を叩き直す必要があります（拾う書類の種類を後から増やしたため）。

**議決権株式数はXBRLに無い。** 【議決権の状況】にあるのは議決権の「個数」で、株数ではありません。単元株式数という項目もXBRLには存在しないため、`議決権株式数 = 議決権の個数 × 100` として扱っています。上場会社の単元株式数は100株に統一されているためですが、前提であることに変わりはありません。検算として `発行済株式数 − 自己株式数 − 議決権株式数 = 単元未満株式` が0以上の小さな数になるかを見られます。

**有利子負債はIFRSの連結からは取れない。** 日本基準は短期借入金・長期借入金・1年内返済長期借入金・社債・コマーシャルペーパーが個別の科目として並びますが、IFRSは借入金をまとめて計上するため同じ名前では拾えません。IFRSの会社については取得していません。

**成功したのにデータが古い、を防ぐ。** スクレイピングが0件でもスクリプトは正常終了するため、Actionsは緑のまま通ります。取得件数が前回の8割を下回ったらサイトを更新せず失敗させ、ページには実際の生成時刻を埋め込んで、4日以上あいたら警告バーを出しています。

## 記述部分（事業・株主・役員）で引っかかったところ

こちらは財務指標とは取り方がまったく違います。

**CSVでは表が壊れている。** EDINETのCSV(type=5)では、これらはTextBlockという形で入っていますが、HTMLタグが除去されてセルの区切りが失われます。`株主数(人)―555143129122587,16588,218―` のように数字が連結し、どこで切るか決められません。そのため提出本文書ZIP(type=1)のiXBRLから、元の `<table>` を解析しています。

**表が入れ子になっている。** 役員の状況は、略歴のセルの中がさらに年月の表になっています。素直に解析すると内側の行を役員一覧の行として拾ってしまうので、深さ2以上の表は行として扱わず、区切りを入れて親セルの文字列に畳んでいます。セル結合（rowspan / colspan）も展開が必要です。

**所有株式数の単位が会社ごとに違う。** 千株・株・百株の3通りがあり、単位なしもあります。千株と決め打ちしたら、ある会社の社長が発行済株式の88%を保有している数字になりました。見出しの括弧から単位を読み、CSVに単位の列を持たせています。

**見出しの位置と表記が一定でない。** 「2026年3月31日現在」だけの行が見出しの上に付く会社があり、1行目を見出しと決め打ちすると表ごと取りこぼします（これで大株主が46%欠けていました）。「氏名又は名称」と「氏名または名称」の両方もあります。位置ではなく中身で判定しています。

**区分名の表記がゆれる。** 「単元未満株式の状況」は全角括弧・半角括弧・括弧なしの4通り、「政府及び」と「政府および」、末尾の（注）の有無もあります。サイト生成時に9種類へ寄せていますが、**CSVは原典どおりのまま残しています**。単位を換算せずに出しているのと同じ方針で、元データを書き換えると後から検証できなくなるためです。

**事業の内容は表ではなく文章。** タグごと落とされると段落の切れ目が分からなくなるので、HTMLのブロック要素で改行を入れて取り出しています。文中に表が混ざる会社もあるため、セルは空白でつないで行ごとに改行します。事業系統図は画像なので入りません。

**同じ人が二重に載る。** 役員一覧は改ページで複数の表に分かれており、一部が重ねて載っています。素直につなぐとニッスイで31名が41行になりました。氏名と生年月日でまとめますが、先に出た行を採るだけでは駄目です。略歴の列が無い表に先に載っている人が略歴を失うため、空いている項目は後から出てきた行で埋めています。

**時系列にはならない。** 財務指標が5年分取れるのは「主要な経営指標等の推移」が1つの報告書に5年分載っているからです。事業・株主・役員は提出時点の断面しか載らないため、毎年の報告書を積み上げることでしか時系列になりません。

## AIによる要約

事業の内容は会社によって数百字から3万字まで幅があり、読むのが大変です。事業タブの「AIで要約する」ボタンを押すと、1行の要約と事業の柱の箇条書きが出ます。

**押されたときだけ作ります。** 全社を一括で要約すると数十ドルかかるうえ、見られない会社のぶんまで払うことになります。一度作った要約は保存され、2回目以降は課金されません。

サイトは静的ファイルだけなのでAPIキーを置く場所がありません。ブラウザに置けば公開されてしまうため、Netlify Functions をサーバー側として使い、保存には Netlify Blobs を使っています。Blobs はデプロイをまたいで残るので、毎朝サイトを作り直しても要約は消えません。

公開サイトなので誰でも押せます。課金が青天井にならないよう3つで止めています。

- 証券コードの形式を検査し、実在する会社のデータしか受け付けない
- 保存済みは課金なしで返すので、連打しても無害
- 1日に新しく作れるのは5社まで（`SUMMARY_DAILY_LIMIT` で変更可）

**要約はAIが作ったものだと画面に明記し、原文は必ずその下に残しています。** 単位を換算せず、区分名も表示時だけ寄せてきたのと同じ方針で、原典を置き換えません。

## ファイル

| | |
|---|---|
| `index.py` | 書類索引の作成 |
| `fetch2.py` | XBRLのCSVから財務指標を抽出・名寄せ・蓄積 |
| `sections.py` | 提出本文書ZIPからHTMLの表と本文を取り出すパーサー |
| `fetch_sections.py` | 事業の内容・所有者別状況・大株主・役員の蓄積 |
| `build_site.py` | サイトの生成 |
| `template.html` | ページの雛形 |
| `probe.py` | 抽出できなかった会社で実際の要素IDを調べる診断用 |
| `data/timeseries.csv` | 財務指標の時系列 |
| `data/business.csv` | 事業の内容（文章） |
| `data/ownership.csv` | 所有者別状況 |
| `data/shareholders.csv` | 大株主の状況 |
| `data/officers.csv` | 役員の状況 |
| `data/dividend.csv` | 配当政策（文章） |
| `data/risks/` | 事業等のリスク（会社ごと） |
| `data/bios/` | 役員の略歴（会社ごと） |
| `data/*_state.json` | どの会社をどの書類で取得済みかの記録 |
| `netlify/functions/summarize.mjs` | 事業の内容をAIで要約する関数 |

**長い文章は会社ごとのファイルに分けています。** 事業等のリスクは1社2万字、役員の略歴は1人数百字あり、全社ぶんを1つのCSVに入れると数十MBになって毎日書き換わります。GitHubの大きなファイルの警告に触れますし、Git履歴も膨らみます。会社ごとに分けておけば、書き換わるのは更新のあった会社のファイルだけです。サイト側も同じ理由で、これらはタブを開いたときにだけ読み込みます。

## 動かす

EDINET APIキーをリポジトリのシークレット `EDINET_API_KEY` に設定してください。

```bash
pip install -r requirements.txt

EDINET_API_KEY=xxx START=2026-01-01 END=2026-01-31 python index.py
EDINET_API_KEY=xxx LIMIT=10 python fetch2.py
EDINET_API_KEY=xxx LIMIT=10 python fetch_sections.py
python build_site.py
```

抽出できない会社が出たら、推測でパターンを足す前に実物を見ます。

```bash
EDINET_API_KEY=xxx SEC_CODES=1950 python probe.py      # 要素IDの一覧
EDINET_API_KEY=xxx SEC_CODES=1950 python sections.py   # 表の解析結果
```

## 出典と注意

出典：金融庁 EDINET（https://disclosure2dl.edinet-fsa.go.jp/）

本リポジトリおよび生成されるサイトは、上記データを加工して作成したものであり、金融庁が作成したものではありません。EDINETの利用規約（公共データ利用規約 PDL1.0準拠）に従い、出典と加工主体を明示しています。取得はAPI経由のみで、4秒間隔・1回あたり財務600社／記述部分300社の上限を設けています。

数値は機械的に抽出したものです。**投資の勧誘・助言を行うものではありません。** 実際の数値は各社の有価証券報告書の原本をご確認ください。

大株主および役員の氏名・住所は、有価証券報告書で公衆縦覧に供されている記載をそのまま掲載しています。
